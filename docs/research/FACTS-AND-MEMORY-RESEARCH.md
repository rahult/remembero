# Research landscape: making Remembero best-in-class for facts and memory

Date: 2026-09-11. Compiled via alphaXiv CLI search + AI digests, cross-checked against
arXiv/OpenAlex. Existing in-repo eval artifacts (`LONGMEMEVAL.md`, `LONGMEMEVAL-V2.md`,
`MEMORY-STACK-BENCHMARK.md`) are treated as baseline knowledge; this document adds what
they do not cover.

Remembero's thesis (proof-carrying memory: Datalog facts/rules/constraints, write gate,
deterministic inference, auditable proof chain) is **orthogonal to nearly everything
published** — the field is overwhelmingly vector/KG-flavored. That is an opportunity:
each line of research below either (a) exposes a capability gap Remembero can close to
be best-in-class, or (b) provides an evaluation stick to prove it already is.

---

## 1. Memory systems worth mining for design ideas

| Paper                        | arXiv      | What Remembero should take                                                                                                                                                                                                                                                                                                                               |
| ---------------------------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AtomMem** (2026)           | 2606.19847 | Closest living relative: **atomic facts** organized hierarchically + graph-based associative recall. SOTA on LoCoMo with **~61% fewer API tokens**. Validate that Remembero's fact extraction produces comparably atomic, non-redundant facts; their redundancy/noise failure modes are exactly what the write gate should reject. Benchmark target.     |
| **Zep / Graphiti** (2025)    | 2501.13956 | **Bi-temporal model** (event time vs ingestion time) with edge invalidation instead of destructive updates. Remembero already has temporal-update tests; adopt bi-temporal provenance explicitly (`valid_from/valid_to` + `recorded_at`) so "what did you believe on March 3?" is answerable. Already the benchmarked external stack — keep it that way. |
| **A-MEM** (2025)             | 2502.12110 | Zettelkasten-style: each memory gets structured attributes + **links to related memories**, and new memories trigger **evolution of existing ones**. Maps to derived rules over fact clusters; their "memory evolution" = Remembero's rule-driven revision, but they do it fuzzily.                                                                      |
| **Mem0** (2025)              | 2504.19413 | Production lesson: explicit ADD/UPDATE/DELETE/NOOP **memory-operation decision** before write. Remembero's write gate is stronger (integrity enforcement), but the explicit operation taxonomy is a good write-path UX and eval surface. Benchmarked already.                                                                                            |
| **MemGPT / Letta** (2023)    | 2310.08560 | Self-directed memory editing via function calls; tiered storage with paging. Reference point for the "memory OS" framing; less relevant mechanistically.                                                                                                                                                                                                 |
| **Generative Agents** (2023) | 2304.03442 | The retrieval-scoring formula (recency × importance × relevance) and **reflection** (periodic synthesis of raw observations into higher-level facts) — reflection maps naturally to _deriving rules from accumulated facts_, a feature Remembero could own deterministically.                                                                            |
| **MemoryBank** (2023)        | 2305.10250 | Ebbinghaus-inspired **decay + reinforcement on recall**. Remembero currently treats all facts as equal; a provenance-preserving salience score (never deletion) would improve session-brief relevance ranking without breaking determinism.                                                                                                              |
| **MOOM** (2025)              | 2509.11860 | Competition-inhibition **forgetting mechanism** for ultra-long dialogues. Niche (role-play) but the forgetting-without-loss mechanics are worth reading if salience/decay is added.                                                                                                                                                                      |
| **HippoRAG** (2024)          | 2405.14831 | Personalized PageRank over a KG for associative multi-hop recall. Remembero's Datalog recursion already does multi-hop _exactly_; HippoRAG is the fuzzy baseline to beat on multi-hop questions.                                                                                                                                                         |

## 2. Temporal representation — the sharpest open problem

| Paper                                  | arXiv      | Why it matters                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Time is Not a Label (ROMEM)** (2026) | 2604.11544 | Names the **"static–dynamic dilemma"**: memory systems treat time as discrete metadata and either destructively overwrite (losing history) or pay for LLM arbitration on every conflict. Their answer: continuous phase rotation + **append-only memory**. Remembero's deterministic take: append-only facts with explicit validity intervals + Datalog rules that resolve "current value" as the latest valid one — same goal, provable, no learned rotation needed. This is arguably the cleanest differentiator story: _temporal conflict resolution with a proof_. |
| **BeliefShift** (2026)                 | 2603.23848 | Benchmark for **temporal belief consistency**: tracking genuine user belief changes while resisting model-induced opinion drift. Finds a stability–adaptability trade-off; RAG helps revision accuracy (+0.09) but not drift. Remembero's write gate + provenance is architecturally immune to silent drift — **run BeliefShift and publish the contrast**.                                                                                                                                                                                                            |
| Temporal Semantic Memory (2026)        | 2601.07468 | No AI digest available yet; flagged from search as on-topic (temporal semantic memory for agents). Follow up.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

## 3. Neurosymbolic/logic core — Remembero's home turf

| Paper                | arXiv      | Relevance                                                                                                                                                                                                                                                                                                                                                                                             |
| -------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Logic-LM** (2023)  | 2305.12295 | Canonical "LLM translates → symbolic solver executes" loop with self-refinement on solver errors. Remembero is this architecture _with persistence and integrity_. Cite as prior art; borrow the **solver-error-driven repair loop** for the natural-language→Datalog translation path (empty-result diagnostics connect to the adversarial review's finding #2).                                     |
| **SymbolLKG** (2026) | 2608.26836 | Logical knowledge graph + **routing to the right solver (Z3, Prover9)** with feedback-driven repair, 78.73% avg across logical reasoning benchmarks. If Remembero ever needs arithmetic/SMT-flavored constraints beyond Datalog, this is the routing pattern to copy.                                                                                                                                 |
| **Formulog** (2020)  | 2009.08361 | SMT-augmented Datalog that scales symbolic reasoning by offloading to SMT selectively. Design reference if the engine needs richer constraint domains (numeric ranges, dates) — Datalog + SMT hybrid without losing proofs.                                                                                                                                                                           |
| **DBSP** (2022)      | 2203.16684 | Automatic **incremental view maintenance** for rich (incl. recursive) queries. Directly relevant to engine performance: with write-gated updates, derived facts/rules shouldn't be recomputed from scratch per query. Incremental maintenance (DBSP or classic DRed/counting) is the principled path to sub-millisecond briefs at million-fact scale — reinforces the `bench:agent-db:million` story. |

## Recommended priority order

1. **Bi-temporal append-only facts + "current value" resolution rules** (Zep + ROMEM synthesis). This is the biggest factual-accuracy lever for multi-session use and produces a killer demo: show the proof of _when_ a belief changed and _why the old answer was once correct_.
2. **Run BeliefShift** (and finish AgentMemBench diligence) — cheap, publishable contrast: drift-immune by construction.
3. **Salience/decay scoring for briefing ranking** (MemoryBank/Generative Agents) — implement as derived, provenance-visible scores; never silent deletion.
4. **Solver-feedback repair loop on NL→Datalog translation** (Logic-LM/SymbolLKG) — compounds with the adversarial-review finding that wrong queries fail silently.
5. **Incremental rule maintenance** (DBSP/DRed) — engineering moat for the million-fact benchmark claim.
